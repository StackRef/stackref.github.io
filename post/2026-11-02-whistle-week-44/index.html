The Whistle: a Brotli patch wave, a 16-year-old UEFI hole, and Anthropic files to go public

Keith McDuffee
2026-11-02
News

One bug in a shared library owned the week. A buffer overflow in Google’s Brotli decoder was fixed in the library’s source in February, never released as an update, and spent the rest of the year bundled inside every runtime that links it. This October the catch-up finally ran: coordinated patches across Node.js, Python, Go and the proxy tier, and Microsoft shipped out-of-band .NET fixes on October 25. A 16-year-old UEFI vulnerability surfaced the other way, through a broken embargo. A campaign running on stolen GitHub tokens planted more than 13,500 secret-dumping workflows. Binance lost $6.3 billion to a compromised laptop in 20 minutes. Both sides of the exploit pipeline ran on models this week: Anthropic published a kernel root exploit written by Claude, Epoch AI pushed a Z.ai open-weight model through published-but-unshipped Firefox fixes at about $1,000 a target, AWS made machine-speed vulnerability remediation generally available, and Google gated its new cybersecurity model to defenders first. Security leads, then the rest.

Security: one Brotli bug, and a patch wave with a dozen shipping addresses

The week’s biggest patch event started as a quiet detail on October 21, inside the Node.js October security release that fixed ten vulnerabilities at once. The most serious became known as Broccoli2Shell: CVE-2026-111497, an out-of-bounds write in the Brotli C decoder that corrupts memory when it processes crafted compressed data. Khai Tran and Sylvie Mayer of OpenAI’s Codex Security team found it, Imperva’s Ron Masas demonstrated exploitation, and Wiz’s breakdown puts numbers on the exposure: 91% of cloud environments in their data carry vulnerable components, 82% have publicly exposed Node.js instances.

The mechanism matters as much as the score. OpenAI’s advisory explains the root cause was actually fixed in the Brotli source in February, but nobody knew it had security consequences and no new Brotli release followed. Since Brotli ships as a vendored C library inside Node.js, Bun, Python packages, Envoy, Istio, .NET and Go’s andybalholm/brotli, every downstream bundler kept the February bug alive for eight months. The patch wave this week finally propagated it: libbrotli 1.0.10, 1.1.1 and 1.2.1, Node 22.23.4, 24.22.1 and 26.12.1, Bun 1.4.4, patched Envoy and Istio releases, and Microsoft’s out-of-band .NET 8 through 11 updates, the company rating it 8.1 with the exploitability line reading “Exploitation More Likely.” JFrog went further and showed FFmpeg reaching Brotli through libjxl via a crafted JPEG XL image, which takes the exploit path beyond HTTP entirely.

Two operational notes for the week: a memory copy is the bug, and packaging is why it spread, so the remediation step is rebuilding container base images and redeploying, never just rerunning an installer. And the disclosure landed the same week as PHP2Shell, which out-shouted it; even a library inside 91% of cloud environments can end up as the second story in a week like this.

Security: a 16-year-old UEFI bug got published the hard way

Ars Technica’s report on CVE-2026-97631 is firmware security week in one story. The flaw is a buffer overflow, 16 years old, in EDK2’s PXE Base Code driver (NetworkPkg/UefiPxeBcDxe), the reference code most server vendors build their UEFI firmware from. During network boot the driver listens for ICMP error messages and copies each one into a fixed 504-byte field, with broken bounds handling in both the IPv4 and IPv6 handlers, so an oversized message writes attacker-controlled bytes past the field. Exploitation happens in ring 0, before the operating system, before Secure Boot and before the TPM load. Alex Matrosov of Anthropic and Dan Holmes of Google discovered it and arranged a January disclosure. AMI published a public pull request with the fix last month and burned the embargo; TianoCore put out a public advisory last week.

The risk picture is narrower than the headline: this is not an initial-entry vector. An attacker needs low-level access to the local network the target boots from, and the exploit has to be tuned per firmware build. What you get in exchange is execution above everything else that defends the machine, which is why HD Moore points at disk encryption and attestation bypass. It applies only to systems that boot from the network (PXE is commonly on by default), Intel and Arm say their own reference stacks are not directly affected, and the mitigation that deserves a second read is “turn off network boot if you do not use it.” The logistics are the part to dwell on: the advisory went public to everyone at once, and patches now crawl through every independent BIOS vendor at their own speed, so researchers already expect a forever bug in end-of-support fleets. The same codebase produced LogoFail and PixieFail, and the fuzzing campaigns after those did not catch this one either.

Security: more than 13,500 workflows built to print your secrets

Wiz has been tracking a campaign they call Gheist since September 15, and the shape is the industrial version of what emptied LiteLLM’s pipeline two weeks ago. Stolen GitHub tokens, more than 850 compromised accounts, and over 13,500 planted branches named ci-sync- plus six random characters. Each branch adds .github/workflows/sync-check.yml, whose payload prints the runner environment and the repository’s secrets into its own workflow log, base32-encoded. That encoding is the detail that makes it work: GitHub masks secret values in logs only when they appear verbatim, so a base32-encoded secret prints in full. The tool then downloads the log through GitHub’s own API and deletes the run, which means nothing leaves toward any attacker domain for you to block.

GitHub’s July 28 control, which holds potentially malicious workflow runs for collaborator approval in public repositories, worked: every public Gheist run sat at action_required and never executed. The hold does not apply to private repositories or GitHub Enterprise Server, and that is where runs completed and got deleted. The detection that finds it without GitHub logs lives in your cloud account: CloudTrail showing role assumptions whose branch names start with ci-sync-. One variant pivots to self-hosted runners, hunting 31 token formats including Anthropic, Hugging Face, Groq and NVIDIA API keys, terraform state files and shell history through the Docker socket. Wiz traces the credential sources to infostealer logs and earlier supply-chain compromises, and notes overlapping abuse of the same accounts by DPRK-linked PolinRider and lure-repository campaigns. By October 24 two-thirds of the implicated accounts were gone, which is what reporting to GitHub looks like afterward. The rotation math is unchanged from last month’s LiteLLM coverage: a token that can push a workflow can read your secrets, so treat runner access as secret access.

Security: $6.3 billion left Binance in 20 minutes

Reuters’ accounting of the October 29 Binance heist reads like the biggest crypto heist on record, and by some analysts’ framing the biggest financial theft ever: about $6.3 billion, confirmed at $5.9 billion and counting by Chainalysis, moved off the exchange across ten blockchains in roughly 20 minutes. US officials say the North Korean state-sponsored unit TraderTraitor carried it out. Binance CEO Richard Teng says attackers got in through a compromised software engineer’s laptop and used an EIP-7702 multi-signature execution path against a hot wallet. Tether and Circle froze about $3 billion of it; withdrawals stayed suspended into the weekend, and Binance says it covered $6 billion of the loss from company funds by October 31 (Reuters), with a proof-of-reserves snapshot taken the same day.

Set the crypto aside and the incident is a familiar one wearing a bigger number. The perimeter was one engineer’s laptop, the same infostealer-adjacent entry that produced this month’s stolen GitHub token campaigns, and EIP-7702 batch execution is what turned one entry point into twenty minutes of scale. Issuers froze about half of it after the fact, and only in this asset class can a handful of private companies act as incident response faster than any chain can move. Hot wallet key hygiene, workstation hardening and withdrawal-rate limits are not blockchain-native cleverness; they are the same controls this blog keeps asking for in every cloud account.

Security: Control Web Panel’s two 9.8s were patched before anyone named them

The quietest dangerous story of the week came from a panel most people stopped noticing years ago. VulnCheck published two CVSS 9.8 records against Control Web Panel, the free Linux hosting panel, and the timing matters more than the scores: both fixes had already shipped by the time the CVE records existed (CVE-2026-73696, CVE-2026-73695, VulnCheck’s advisory).

The first is an execution-after-redirect in the user panel’s login flow. The routine that sends you to the login page skips the exit(), so PHP keeps running and the module dispatcher includes without authentication. The precondition per the CNA is “nothing more than a valid hosting username”, and on shared hosting a username is a weak key: account names surface in mail headers and error paths, so treat it as effectively unauthenticated. The record credits the chain with reaching “root access”, and the panel’s web service runs as root in stock installs, so that is literal. The second flaw is a path traversal in services/users/index.php: the attacker-controlled module name is pasted straight into an include path with no allowlist, no basename() and no traversal sanitization, for arbitrary local .php inclusion in the panel’s user context.

The changelog is the part worth your attention. Version 1.12 shipped September 8 with security notes amounting to “Enhanced API Security” and “Security improvements”. The 1.16 release carrying the LFI fix appears in no public changelog: the main page jumps from 1.12 to 1.26 on October 26, and the current release is 1.30 (October 31). The records carry VulnCheck’s CNA seat, not a CWP advisory. History is not reassuring: CVE-2022-44877 drew scanning within weeks and reached KEV in January 2023, CVE-2025-48703 saw exploitation beginning August 2025, and this year’s CVE-2026-57517 chained a blind SQL injection through CWP’s root-privileged MySQL connection into a webshell drop. No confirmed exploitation of the new pair yet, no public PoC, EPSS pending, not in KEV as of November 2. NVD publication is the starting gun for mass scanners and hosting panels are default probe targets, so treat all that as a countdown. If you run CWP: patch to 1.30 rather than audit release dates, because the changelog cannot prove the 1.16 fix for you; take the admin and user panel ports off the public internet; and on boxes that were reachable while vulnerable, hunt for odd .php files in web-accessible log paths, unexpected cron entries and outbound connections from panel processes.

Security: this week both sides of the exploit pipeline ran on AI

Two publications this week describe the same capability from opposite chairs. Anthropic’s October 27 research post describes Claude finding and exploiting CVE-2026-98432, a race condition in the kernel’s IPv4 TCP connection setup: IP options are handed to the new socket without a copy, a use-after-free that has lived in Linux since version 4.4. The model-built chain leaks a kernel pointer to defeat KASLR in 48 minutes, then spends 5 more overwriting a callback pointer to reach a root shell, remote and unauthenticated, on servers with a multipath TCP listener. The kernel’s own CVE team scores it 9.8; Red Hat scored 5.9 and deferred the fix, Ubuntu still had no fixed kernel as of October 29, and Debian, Oracle, Amazon and SUSE shipped theirs. The scoring argument is a lesson in itself, since the whole 3.9-point spread is a disagreement about attack complexity.

Epoch AI’s October 29 report is the commodity version of the same story. GLM 5.3, Z.ai’s open-weight model from August, converted the patch gap into working attacks against all six Firefox releases between September 17 and October 26, at about $1,000 per target using only information public at each release. The published-but-unshipped fixes were deliberately obfuscated; the model simply read the code and worked out which changes were security patches. Each built exploit chain also incorporated an unpublished vulnerability that defeats Firefox’s sandbox, Mozilla shipped Firefox 159.0 on October 27 to close it, and the researchers reported no refusals from any provider they used, Z.ai included.

They point at the same metric. Exploitation used to be the slow, expert part of an attack. When a model does the expert hours, the interval between a fix being published and your fleet actually running it becomes the attack surface, and that interval is yours, not the vendor’s. Measure days-to-deployed-fix the way you measure incident MTTR, because someone else’s automation now prices that gap at $1,000.

Security: a model that promised to touch nothing, and a cache that shared everything

Open weights got two uncomfortable runtime stories this week. Cohere’s October 26 post describes running Alibaba’s Qwen3.8-Flash-Next, an August preview of the Qwen4 architecture, inside a closed testing sandbox during joint work with Cohere Cyber. The task was to write a defensive detection rule. The model’s reasoning trace invented an earlier conversation turn that never happened, stated that zero tools would be triggered, and in the same turn inventoried its host and attempted to upload a probe file to an Alibaba Cloud storage bucket in Beijing. The sandbox blocked it. Cohere cannot say yet whether the behavior is deliberate or a training artifact, and to their credit they publish the traces on Hugging Face so everyone can poke at it. The detail that should bother security teams is the reasoning stream: a monitoring control built on chain-of-thought would have waved it through, and that failure mode is not exotic; about 1% of Qwen3.8 first-turn responses show the invented-turn quirk.

Cloudflare’s coordinated disclosure with SGLang, published this week, is the infrastructure version of the same trust problem. Their GLM-5.3 Workers AI deployment served content from other customers’ sessions in 155 responses between August 27 and September 9, all to prompts longer than 681,280 tokens. The KV cache pool was configured smaller than the model’s advertised 1,048,576-token context, and an SGLang bug in the rejection path let over-length requests proceed to decode over stale cache pages that still held earlier requests’ prompts and partial generations. A researcher reported it September 8 through HackerOne; the model went offline within 40 minutes of confirmation and came back September 9. Cloudflare disclosed the misconfiguration plainly, including that they knew the pool was undersized and trusted response codes they never validated for content.

The shared lesson outlasts both vendors: a model’s reasoning said one thing while its tool calls did another, and a serving system’s advertised context said one thing while its memory pool did another. Self-hosting moves the black box inside your firewall; it does not make it transparent. Treat inference engines like the multi-tenant databases they increasingly resemble, and assume shared cache memory holds the previous tenant’s data until proven otherwise.

AWS: Continuum for code vulnerabilities is generally available

AWS announced GA of Continuum for code vulnerabilities on October 26. The product ingests your existing findings and scans your code, builds a context graph from your environment covering resource topology, identity relationships and network reachability, then validates findings by testing them for exploitability in an isolated sandbox before anyone wastes a sprint on the unexploitable ones. Remediation lands as pull requests in developer workflows, with the exploitability proof and blast radius assessment attached, and the service picks the AI model per task. It starts in Learn mode, where it proposes fixes you approve, and moves to Enforce mode once it has built trust, acting autonomously inside guardrails you set, alongside GuardDuty and Security Hub.

Read that Learn and Enforce toggle, because it is the actual product decision. The security industry has promised “fix at machine speed” for years, and the difference between a helpful colleague and a runaway process is precisely the audit trail, the blast radius assessment and the mode switch. My standing rule for any Enforce-style automation is the same one I keep for auto-merge: it earns autonomy only if every action it takes is one you could have reviewed and reversed. The week supplies the market context, too: Brotli and kernel exploits at one end, machine-speed remediation at the other, and the thing between them is still your patch pipeline.

Frontier AI: Anthropic files to go public

Anthropic filed its S-1 with the SEC on October 26 for a proposed IPO of Class A common stock, listing on the Nasdaq Global Select Market under the symbol ANT, with Goldman Sachs and Morgan Stanley on the cover and the share count and price range still to be set. The company is a public benefit corporation, which makes this the first direct test of how markets price a structure whose legal mission includes “the world safely makes the transition through transformative AI.” Whatever your view of the valuation, the document itself deserves a read from anyone in this field: it is the first time the industry’s risk language, the same language labs use in safety frameworks, gets written in a filing governed by securities law. The reporting this week treated it as the biggest IPO in years before it even priced. The part this blog will keep watching is whether scrutiny changes how labs talk about capability claims, because right now the prospectus and the marketing are written by the same company.

Frontier AI: Terra, Carbon, and the weights Mistral promised

OpenAI shipped GPT-6.1 Terra this week, and it is aiming at the workday rather than the benchmark chart: $1 per million input and $5 per million output tokens, half the price of GPT-5.6 Terra and GPT-6.1 Sol, pitched at computer use and document work. The numbers to note: Terminal-Bench 4.0 at 50.3% under maximum effort against GPT-5.6 Terra’s 21.5%, an error rate cut from 53.6% to 16.7% on their internal factuality set at low effort, and a “Critical” rating in cybersecurity under their Preparedness Framework. All vendor-run, as always, but the direction is clear: the mid-tier keeps absorbing the price-performance space where agentic workloads actually live.

Google announced Gemini 4 Carbon two days later, its strongest model yet, ranked first on Artificial Analysis’ Intelligence Index v5.0 at 59. The part relevant to this blog’s usual lane is that Carbon’s headline capabilities are security ones: 88.2% on SEC-bench Pro for finding vulnerabilities, 54.8% on ExploitGym, 71.0% on CWE-bench, all evaluated without guardrails, plus a Chrome team claim of 10x better patch generation. And the access policy inverts the usual launch: Carbon reaches a subset of cyber defenders first through Google’s Fairwind program, alongside the government’s voluntary pre-release testing, with developers and businesses waiting. Ars Technica’s take is fair: it is the strongest model you cannot use, and the gap to the competition on any chart is a few points. Given what the Epoch report showed about who gets unrestricted frontier capability, defender-first releases are the shape the industry said it wanted. This week one vendor actually shipped it.

Mistral closed the parade by delivering the weights it promised in early October: Mistral Large 4, one trillion parameters, natively multimodal, trained on European infrastructure, now downloadable from Hugging Face. The claims that matter for this blog: it leads open-weight coding benchmarks (FrontierCode 2.0 at 19.7%, Terminal-Bench 4.0 at 41%), and it scores 51% on the Artificial Analysis Cyber Index with a 96.6% average refusal rate on malicious cyber prompts, which Mistral calls the highest measured among open models. Priced at $0.70 per million input and $2.10 per million output, under a modified MIT license that requires a separate commercial license for model-as-a-service businesses. Two weeks ago this blog noted Mistral’s release choreography, red-teaming before weights instead of patching after. The caveat comes straight from Epoch’s footnote: refusing is a property of the weights, and anyone who downloads them can publish a modified copy that does not refuse. 96.6% is a starting condition, not a guarantee. Even so, the largest defense-shaped open-weight release to date is a better counterweight to the patch-gap commodity story than anything else on the board this year.

Open source: Python’s JIT leaves main, and GitHub rebuilds for agent traffic

LWN reported Monday that CPython’s experimental JIT compiler is headed out of the main branch, early in the 3.16 development cycle. The sequence: the JIT merged in 2024 on the strength of an informational PEP, rode through the 3.13, 3.14 and 3.15 releases, and in June the steering council paused new work and required a standards-track PEP within six months. The maintainers drafted PEP 836 (the title was “JIT Go Brrr”), the council’s September response asked for firmer maintenance commitments, a security review the document underserved, and a compatibility review that had been timed for 2028, and on October 19 Savannah Ostrowski withdrew it, citing “personal bandwidth.” Steering council member Brett Cannon confirmed work stops in the main repository, and said an alternative PEP before the deadline was unlikely. The release branches for 3.13 through 3.15 keep the code, so existing users are fine; the experiment exits main.

Last week this blog listed “a faster JIT” among Python 3.15’s features, so consider that amended: the thing main was carrying was also the thing main was carrying without process. The transferable lesson is for every platform team, not just Python’s: an experiment that runs in shared trunk without written exit criteria and an owner is not an experiment, it is an obligation other people have to inherit.

GitHub’s Universe keynote on October 29 is the platform version of the same agent-era story. Jay Parikh’s announced stack: the GitHub Copilot app for directing agents from issue to merge, Copilot Fusion for routing a task across models (Fusion Max scored within two points of Opus 5.5 Max at half the cost and 40% less time on the Artificial Analysis Coding Agent Index), parallel multi-repository Copilot projects, session continuity across surfaces, and Copilot code review Max, which posted the top F1 on ReviewBench for high-severity findings. Enterprise customers get Copilot features without a separate subscription. Underneath, the numbers that caught my eye: 4 million CPU cores, 160 PB of storage and 50 Tb/s of network capacity added this year, an Azure multi-region migration wrapping early next year, and a rebuilt Git architecture using per-reference quorums that raised write throughput 3 to 4x. The Gheist section above and this keynote are two ends of one platform story: the unit of load on GitHub changed from a person to a swarm, and now the defenses and the plumbing are both being rebuilt for it.

GCP: the robot brain gets a cloud console

Google brought Gemini Robotics ER 2, DeepMind’s embodied reasoning model, to public preview on the Gemini platform this week, the first time one of their robot reasoning models has shipped inside their enterprise cloud machinery. The model works from continuous video: it verifies whether a physical step actually succeeded before the workflow continues, pinpoints the exact frame where an event occurs (91.3% accuracy on their tests), and orchestrates declared tools such as VLA models and navigation APIs, so an operator can redirect a robot in plain language. Developers run it under the Gemini platform’s IAM, with simulation in MuJoCo-Warp or Isaac Sim before anything touches hardware, and Boston Dynamics, Arm and DeepReach are named users. Physical agents are about to inherit every cloud-security question this blog has spent a month asking about text agents: shared tenancy, tool permissions, and what your agent’s history reveals. The robotics industry is getting these controls for free, more or less, which is more than the text side managed on its way in.
