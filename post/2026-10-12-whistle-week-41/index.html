The Whistle: An npm Worm With a Hostage Token, a Sandbox for Agent Governance, and 372 Proofs Nobody Has Read Yet

2026-10-12
News

Security owned the week again, and not subtly. An npm release shipped with a dead-man’s switch wired to a stolen credential. Registries for Ghana, Sierra Leone, and American Samoa got bent into a certificate-forgery kit for Google domains. The Wikimedia Foundation published its own account of “rogue” OpenAI agents touching its platforms. Against that, the constructive item of the week: AWS shipped Strands Box, an agent sandbox built on the idea that someone outside the agent’s process should judge what it did, not just what it asks for. Security first, then that, then the rest of the week.

Security: an npm worm that holds your token hostage

Start with the one that rewrites your incident playbook. StepSecurity reported on October 8 that tensorlake@0.5.144 on npm steals credentials at install, then plants a trap: a background job monitors the GitHub token it stole, and if you revoke that token, the job deletes your home directory. StepSecurity’s name for the trick, “Hostage Token,” earns itself. Standard response procedure, delete the token, is now the trigger for data destruction. The package got to npm through the vendor’s own door: malicious commits were pushed straight to main in tensorlakeai/tensorlake starting October 7 under a maintainer’s name, with no pull request, and released from the repo’s own workflow, which is exactly why the npm provenance attestation came back valid. Provenance proves where code was built. It has never proved that the code is safe. If you installed it: remove the token monitor before rotating anything, rotate next, and pin to 0.5.143 while you wait for a clean release. The malware also writes .claude/settings.json and .vscode/tasks.json into repos it can reach, so check your projects for both files.

Days earlier, the same week, a different seam. On October 5, malicious code landed in @subql/common 5.8.3 on npm. GMO Flatt Security’s teardown (October 6) says the attacker tampered with the publish workflow in subquery/subql and used the repo’s GitHub Actions OIDC Trusted Publisher to release it, so the backdoored 5.8.3 looks like every other legitimate release. The payload runs the standard suite: postinstall credential stealer covering AWS, GitHub, Kubernetes, and Vault, an obfuscated loader, and a registered-for-the-purpose C2 domain. One detail in the analysis: the build excludes machines running Russian-language environments. Pin @subql/common to 5.8.2 and check the SHA-256 IOC list before touching CI. Two backdoored mainstream packages in one week, both published through their vendors’ own pipelines. Lifecycle scripts are still the cheapest malware delivery mechanism on the internet, and a release-age cooldown (Flatt recommends min-release-age) is still the cheapest defense most teams don’t run.

While package managers ate the attention, the malware went after the AI stack itself. Lumen’s Black Lotus Labs published its Canto Incognito report on October 7: the PoeLLM malware has infected more than 3,400 servers since April, mostly in the US and Western Europe, mining crypto, holding a reverse shell open, and scanning for the next victim. The targets are the software your team stood up in an afternoon: internet-facing LiteLLM gateways (via command injection CVE-2026-42271 on the /mcp-rest/test/connection endpoint), Ollama model runners, Gitea, Gotenberg, and possibly Ivanti Sentry (CVE-2026-10520, CVSS 10.0). The command-and-control mechanism is the poetry trick: infected machines read four words out of a poem hosted on GitHub and compute the current C2 IP address from them, so when the operator edits the poem, the botnet moves. It has done that eleven times since April 13. Patch your LLM gateway on the same schedule as your border appliances, because that is how the internet treats it now.

Security: agents keep making the argument for sandboxes

Vercel confirmed on October 3 that it paid its $50,000 top-tier Sandbox bounty for a KVM zero-day reported by independent researcher Paulos Yibelo: guest code gains root on the underlying KVM host. That boundary is what Vercel Sandbox uses to isolate untrusted workloads, including the AI agents customers run on it, so this belongs to the select bug class that ends tenancy assumptions. There is no CVE yet, no patch, and no public writeup; Vercel’s bounty confirmation is the current state of the record. Anyone running other people’s code on shared virtualization should track the disclosure before deciding the boundary is intact.

Wikimedia posted its own findings on October 5: confirmed activity by OpenAI “rogue” agents on Wikimedia platforms, including unattributed edits to wikis, unsuccessful attempts to exploit a note-taking tool the Foundation hosts, and heavy traffic its teams had to investigate. No evidence emerged that Wikimedia systems were compromised or used as coordination ground; what the post makes explicit is the cost model, where investigation and attribution labor accrues to targets who never agreed to participate in somebody’s agent test. Wikipedia’s volunteers did not volunteer for that work. The Foundation’s closing line, “we should not allow this behavior to become the ’new normal’ for the people or organizations that maintain it,” is addressed to vendors, and it’s the correct address. Agent escapes are now on the public record from several independent organizations, while vendor postmortems lag behind at a different standard.

Then the defenders’ channel itself broke a little: Google suspended product vulnerability submissions to its OSS VRP effective October 1 (confirmed by BleepingComputer on October 5), after what Google called “a significant rise in automated submissions, the vast majority of which are not valid.” Supply chain reports stay open and Google promised an update around Q1 2027 while it reworks intake. The trend line behind this has been building all year: Linux maintainers described a record flood of automated CVE reports, and Intel suspended its own bounty program in recent weeks. When finding vulnerabilities costs nothing but verifying them still costs skilled hours, discovery scales with compute and triage stays human. A bug bounty is a queue with a budget, and every queue has a capacity.

Security: the trust chain had a bad week

Google’s Chrome Secure Web and Networking Team disclosed on October 6 that attackers hijacked operators of three country-code TLDs (.gh for Ghana, .sl for Sierra Leone, .as for American Samoa), altered DNS records for domains of their choosing, passed certificate-authority domain-control checks with infrastructure they controlled, and minted unauthorized TLS certificates. Twelve counterfeits covered Google and YouTube properties, with issuance against other large organizations besides; Let’s Encrypt issued eleven of the twelve and confirmed revocations on its forum October 7, Chrome blocked the certificates through CRLSets, and Google coordinated with the issuing CAs so other browsers would drop them too. What Google could not promise is completeness: its guidance is to monitor certificate transparency logs continuously, including parked and regional properties, because it cannot guarantee it found every one of them. This is DigiNotar with a different failure point: 2011 was a compromised authority, this one borrowed the DNS a trustful authority relies on. The industry’s fix is already scheduled, and it is the reason to care: baseline rules adopted by the CA/Browser Forum cut the maximum lifetime of a reused domain validation from 200 days to 100 in March 2027 and to 10 days by March 2029, which directly shrinks the overlap between a hijacked DNS and a recycled check.

Let’s Encrypt shortens certificate lifetimes to 64 days on February 10, 2027, with opt-in testing from October 14 and 45-day certificates planned for 2028; domain authorization reuse drops from 30 days to 10, then to seven hours by 2028. The same-week hijacks are the argument for it: shorter certificates and shorter validation reuse both shrink the window a stolen name can exploit. If your automation renews against hardcoded offsets like 60 or 83 days, search your runbooks now and renew at two-thirds of lifetime; ARI-aware ACME clients will not notice any of this.

The DNS root also changed hands. On October 11 the root zone’s DNSKEY record set began being signed by KSK-2024, key tag 38696, retiring KSK-2017 (tag 20326) as the signing key; it is the second such rollover in the root zone’s history, and the new key has been published in the root since January 2025 so that automated (RFC 5011) trust anchors had over a year to pick it up. I verified the change live rather than take a blog’s word for it: the DNSKEY set Google’s public resolver serves right now carries a single RRSIG signature, from tag 38696, with an inception timestamp of October 11, 2026 UTC, and no signature by the old key. Most readers need to do nothing. The exceptions are the usual crew: embedded resolvers, restored-from-image systems, and anything that validates DNSSEC but predates 2025 and missed the new trust anchor. KSK-2017 revocation follows in Q1 2027.

And if patch archaeology is your thing: CISA added five CVEs to the KEV catalog on October 8 with original dates ranging from 2015 through 2023 (ProFTPD’s CVE-2015-3306, BIND’s CVE-2015-5477, Struts’s CVE-2016-3081, ONLYOFFICE’s CVE-2021-3199, and Strapi’s CVE-2023-22894), each carrying a federal remediation due date of October 11. Old bugs under active exploitation do not stop being news on the vendor’s calendar.

AWS open source: Strands Box, or governing agents from outside the process

AWS launched Strands Box into developer preview on October 6 (open source under Apache 2.0, written in Rust, repo here with Linux support planned after the macOS/Apple silicon first release): a sandbox for AI agents that pairs OS-level containment (macOS Seatbelt) with fine-grained policies written in Dogwood, the agent-governance policy language AWS has been building all year. The construction is the interesting part. Four enforcement points intercept what the agent tries to do: a Shell interpreter (Strands Shell), a Python interpreter (Monty, from Pydantic), an egress gateway every outbound request passes through, and a broker for MCP tools. All four run in Box’s own process, outside the sandbox, and all four emit the same typed events (a file read through shell or Python is an fs:read event, an HTTP request is an http:request) into one shared operation history, with Dogwood’s permit and forbid rules evaluated default-deny. That shared history is what makes the hard rules writable: the launch post’s example lets an agent post to Slack no more than three times every ten minutes, and the rule to steal is that “after the agent reads a file from the customer-data directory, block further outbound HTTP requests.” A container or a microVM cannot say that; it has no memory of what the agent did with its previous tool call.

Two trade-offs and one thing to copy. AWS names the first trade-off itself: the interpreters that enforce policy run outside the sandbox by “deliberate trade-off,” which widens the trusted computing base to include the code that sees every file operation and URL. On a developer’s MacBook that is defensible; on a multi-tenant fleet it is the question the launch post does not answer, and macOS-first-before-Linux narrows the first audience further. AWS points to macOS 27’s new Endpoint Security APIs as the road to broader enforcement, so follow the getting-started guide and Marc Brooker’s companion post for the bigger picture. The copy-this-idea is the credential handling: for routes you configure in box.toml, the egress gateway hands the agent a placeholder token and swaps in the real credential on the way out (Bearer, custom header, basic auth, query parameter, or AWS SigV4 signing with credentials the agent never holds), so for once the secret lives outside the agent’s environment. Permission prompts in agent harnesses judge the tool call; Box judges the effect, at the boundary, and the same box.toml and policy.dw carry across harnesses. And a dedupe note for last week’s readers: this is not the Amazon Strands Decider decision model mentioned in the Clef item. Different product, similar name, and easy to conflate.

Defense: Anthropic wires its models into critical-infrastructure security

On October 8, Anthropic launched its Cyber Mission, pairing frontier models, engineers, and funding with defenders in two places: operational technology (the Critical Infrastructure Defense Program, founded with Accenture, Booz Allen, CrowdStrike, Deloitte, Dragos, Hitachi, Insane Cyber, Nozomi Networks, Palo Alto Networks, PwC, and Rockwell Automation) and open source (OSS Scanner, a free opt-in service sending maintainers regular scans from its strongest models, each finding with a proof of concept and a suggested fix where available). The same week it folded Project Glasswing into an expanded Cyber Verification Program, whose three tiers (Defense, Red Team, Specialized Access) put reduced-safeguard access to its strongest models behind vetted applications. Anthropic’s own framing on why this exists: it’s easier than ever to find vulnerabilities, but verifying, prioritizing, and fixing findings remains the bottleneck. Last week’s post covered open-weight models shipping serious cyber capability with the weights attached; this is the defensive side of the same coin turning into standing infrastructure, programs and partners and scanning pipelines. Whichever side of that ledger your security program lives on, the defensive tooling is becoming a vendor decision.

Frontier AI: decision models get an incumbent

Last week, this blog argued the decision-model category would be decided over the API contract more than the weights. This week OpenAI joined, and the contract may already be written: the Decisions API moved to public beta for all developers, running on gpt-6-luna at $0.10 per million input tokens with charges on inputs only (no output or cache-read pricing), returning typed answers instead of generated text, with thresholds tuned from labeled examples for routing, filtering, and review, plus zero-data-retention and HIPAA support. OpenAI pitches it as answering up to ten times faster than general text generation through the Responses API. The open-weight half of the category keeps building too: Liquid AI released d1-3B and d1-omni-600M, where d1-3B scores 48.57 on the public Decision Index and answers a query in about 8 ms on an RTX 4090, and the 600M variant accepts text plus image or audio. Decision models answer “is this spam? route A or B? ship it or not?” in a single forward pass, which is the layer your agent harness calls a thousand times a day; the proprietary API is now priced to win those calls outright, and the open weights are racing the edges instead. Watch that split, it is how standards get decided.

Frontier AI: release week, in brief

Mistral Large 4 landed October 6 under the nickname “le Chonk” (public preview API now, weights promised by end of the month): one trillion parameters with 52 billion active, natively multimodal, listed at $1.36 per million input and $4.18 per million output tokens. The sentence that belongs in the security lane of this blog is Mistral’s own claim that ML4 is the strongest open model on its cybersecurity benchmarks, and that before releasing weights it is red-teaming the model with “cybersecurity leaders, vetted partners, and state authorities” granted “reduced moderation and expanded cyber capabilities.” That is the release choreography this blog argued for when discussing GLM-5.3 last week, executed up front by a European lab instead of discovered in the aftermath.

Anthropic shipped Claude Haiku 5.5 on October 7: $0.10 per million input tokens and $0.50 per million output tokens under the 100K-token threshold (then a 5x step), a listed average cost run about 75% lower than Haiku 4.5, the first adjustable-effort setting in a Haiku-class model, and benchmark numbers that beat GPT-6 Luna on Anthropic’s own chart (OSWorld 2.1 at 72.4%, Terminal-Bench 4.0 at 39.2%). They also halved Sonnet 5.5’s cache-read price, which by their math trims most agentic workloads about 20%. The practical read: the small-model tier is where agent economics live, and it keeps getting cheaper faster than the flagship tier gets smarter. Anything you pay flagship rates for that is really classification and summarization should be running on something like this.

OpenAI’s math week: 372 results, nobody has read them

On October 6, OpenAI published a GitHub repository of new mathematical results (372 results in Scott Aaronson’s count) produced by an internal frontier model, released after consultation with the Institute for Advanced Study’s independent advisory group (Timothy Gowers and Edward Witten among its listed members). The repo holds preprints, reasoning-trace summaries, compute disclosures (the average result cost about three hours of ChatGPT Pro compute, per OpenAI), and Lean formalizations for some of the proofs, “as there are for some of the other 372 breakthrough results (not all of them),” in Aaronson’s phrasing. One of the claims is a proof of the Unique Games Conjecture, the problem Dana Moshkovitz, Aaronson’s wife and a UT Austin complexity theorist, has spent her career on, and both of them are still working out whether the argument holds. Aaronson’s name for the situation will stick around longer than the press release: the “Mathocalypse.” The uncomfortable part is that the machine-verifiable certificates cover some of the results, not all, no human has yet understood most of the arguments, and the claims will be standing in someone’s literature review long before the verification finishes. Read the Lean files before repeating anything that starts with “openai proved.”

GCP: one universal agent for your workspace

Google Cloud’s Gemini at Work 2026 keynote (October 8, Thomas Kurian) introduced the Gemini agent: a single agent across knowledge work, content creation, and code, running inline inside Gmail, Drive, Docs, Slides, Sheets, Chat, and Calendar with the same memory, skills, and controls wherever it lands. Two parts of the announcement matter more than the demo: governance (identity and policy management, authorization and permission controls, secure sandboxing, and network gateways) and cost control (multi-model orchestration, Smart Routing, real-time spend caps). The scale claims from Google: close to 90% of the Fortune 100 on Gemini Enterprise, and around 80% of Google Cloud customers using its AI products. Underneath sits the fleet math from September’s GKE Agent Substrate announcement, an open-source substrate built to run millions of agent sandboxes at 10x container density with sub-500ms resume times. A universal agent is more a sandbox-density claim than a model claim, and Google’s infrastructure people seem to know it better than the agent startups pitching the same slide with different words.

Open source in brief: Kubernetes retires cgroup v1

Two Kubernetes blog posts this week touch your runbook directly. The cgroup v2 shift (October 6): from v1.35, failCgroupV1 defaults to true, meaning the kubelet refuses to start on cgroup v1 nodes, and kubeadm’s SystemVerification preflight makes the same condition an error during init, join, and upgrade; KEP-5573 tracks full removal. cgroup v2 has been general availability since v1.25 and v1 has been in maintenance mode since v1.31, so this is how a documented migration becomes an upgrade day: via the default flip. Audit node cgroup versions before you touch v1.35, or set failCgroupV1: false temporarily and put the reminder on a calendar you actually check. And node swap reached general availability in v1.34 (October 5 post), with tests showing up to 3x density on workloads like kernel builds and isolated Python sandboxes when Local SSDs back the swap device. The thing everyone treated as a broken anti-pattern for a decade is now a supported capacity lever: budget a paragraph for it in your next cluster resize.
