The Whistle: Root Through a Mail Gateway, an Intrusion Run on 51 Agents, and Deno's Clock Starts

2026-10-19
News

The appliance beat returned to the top this week: a mail gateway and a VPN, both rooted through unauthenticated bugs that were in use before they had fixes. Below them sits the more interesting story: an initial access broker ran a campaign on Claude Code, a cluster of 51 specialized agents, and an open-source pentest framework, then leaked its own working directory, so the intruder’s playbook is readable in its own session logs. Appliances first, Meta’s GitHub and the agent stories after, cloud and model news closer to the end.

Security: the mail gateway and the VPN, again

Cisco disclosed CVE-2026-76519 on October 14: CVSS 9.8, in Secure Email Gateway’s Advanced Malware Protection, caused by improper handling of email attachments. One malicious attachment hands a remote, unauthenticated attacker file writes and root command execution on the appliance. Exploit conditions: the File Reputation service must be enabled on a mail policy and the installed Content Scanner Tools must be older than 25.3.0.5525. The fix is an upgrade to AsyncOS 16.5.0-780, and there are no workarounds. CISA cataloged it October 14 with a federal deadline of October 17. Both Cisco and CISA confirm active exploitation, and Cisco has declined to say how many appliances were hit or what attackers did with access. The part that should retire the “email security is a purchase, not a patch cadence” mindset: this is the second SEG zero-day in two months (September’s CVE-2026-76461 has the same mail-attachment-to-root shape), the third in a year, and January’s CVE-2025-20393, which attackers used to install persistence, scored 10.0.

Ivanti’s entry is worse in a more useful way. CVE-2026-104935, an authentication bypass in Connect Secure (the former Pulse SSL VPN), needs nothing from the user and yields command execution on unauthenticated requests. Volexity’s writeup goes further: on a fully patched appliance (22.8R2.4), a threat actor they track as UTA0576 chained the bypass with a second flaw and a privilege escalation bug for unauthenticated root, starting October 3 (Defused saw the first in-the-wild signs October 1; Ivanti confirmed limited exploitation). The part that matters for triage: no malware and no web shell left behind. The attacker re-exploited the device for each command and tampered with logs, specifically to defeat Ivanti’s Integrity Checker Tool, the check every Ivanti advisory tells you to run. What the session contained instead was credential theft, Active Directory recon, and exfiltration. As of this writing the privilege escalation component is still unpatched, Shadowserver counts 5,500+ internet-exposed instances, and for some branches the fix means migrating to new hardware (25.1.3.0 requires the ISA4500/6500/8500 platforms). If your Integrity Checker Tool reports a clean bill this month, treat that report as worth less than it was two weeks ago.

The KEV catalog confirms the appliance reading: nine CVEs added October 13 through 16, including the Cisco mail gateway and Ivanti bugs above, a Windows Shell bug from record Patch Tuesday (CVE-2026-96951, exploited in the wild), the Atlassian Data Center bundle (CVE-2026-21589), a PAN-OS code injection (CVE-2026-0322), BeyondTrust Remote Support (CVE-2026-102764), the AhsayCBS backup-server pair that Huntress watched get web shells and crypto miners (CVE-2026-105133/105134), and a 2025 Fortinet path traversal (CVE-2025-61624). KEV entries carry federal due dates and, more to the point, proof of use. Patch anything on this list today.

Security: Meta’s GitHub repos got popped

Meta is notifying about 1,500 people (October 13) after an outside group used an employee’s stolen credentials to enter some of the company’s GitHub repositories; the intrusion was detected a few weeks ago, access was shut off, and GitHub and law enforcement were brought in. The accounting: 99% of what was taken was business data, code related to some of Meta’s products; the remaining 1% was personal data that policy forbids in the repos, mostly belonging to US employees who were offered credit monitoring. Meta adds that much of what looked like personal data was synthetic or anonymized test data, so attackers may not be able to tell the real records apart. It has not said exactly what the personal data was or named the repos.

Two things stand out. First, the 99% figure inverts what a number like that usually means in a breach notice, because the code is the asset here. A competitor or a malware author reading Meta’s source gets a map of internal architecture, and no identity-theft checklist captures that kind of loss. Second, personal data in those repos contradicted Meta’s own written policy. So audit your own repos against your own policy before the disclosure comes from the other direction.

In the week’s other breach accounting: CenterPoint Energy told Texas authorities that 1,062,060 residents had names, addresses, Social Security numbers, and driver’s license numbers taken, a month after an SEC filing that followed the hacker’s leak of a 2.5 GB archive (the claim on the crime forum was 7.5 million records, and the utility also serves Indiana, Minnesota, and Ohio, so the full count is likely higher). Individual notification letters have apparently not gone out.

Security: agents on both sides of this week’s tape

The defensive case first. Noma Labs disclosed “SneakPeek” on October 14, with Dark Reading’s account as a good summary: Claude Code Desktop’s preview pane auto-renders HTML that Claude generated or edited, and the renderer leans on three defenses (a Content Security Policy, origin isolation, and a request filter). A file padded past 256 KB gets loaded through a file:// URL instead of a data: URL, which skips the CSP, and the request filter only arms itself in the proxied dev-server mode, not for static files. Clone a repo carrying a plausible oversized “coverage report,” ask Claude to review or edit the file, and the render happens automatically: JavaScript runs, file:// fetch() calls resolve against your actual filesystem, and the loot (SSH private keys, AWS credentials, npm and GitHub tokens, Kubernetes secrets, registry auth, your real IP via WebRTC) goes back out through sendBeacon(). Anthropic scored it CVSS 8.7 and treated it as equivalent to host code execution. The timeline is worth reading whole: July 4 report, July 9 first fix, a July 24 bypass through a blob-URL Web Worker, and the real fix on August 17 in Claude Desktop 1.30096.1, delivered by auto-update. What puts this one in front of your team isn’t the pending CVE: no tool call was ever approved. The model read a file and the product rendered it, and permission prompts cannot intercept a side effect of rendering. That is the same argument this blog made a week ago in Strands Box’s favor: judge the effect, not the request.

The offensive case: SOCRadar profiled an initial access broker it calls CyberXero, with The Hacker News’ October 12 write-up a solid digest: active since at least July, running Claude Code with a cluster of 51 specialized agents on the attacker’s workstation and PentAGI wired to Cobalt Strike for payload delivery. One automated pipeline works WordPress and e-commerce sites at volume (one run scanned 4,708 targets, confirmed 429 admin panels, and deployed 32 web shells inside 61 seconds) plus exposed Redis servers; a curated pipeline works Ukrainian energy and critical infrastructure manually, including a heating provider in Kharkiv. Confirmed exfiltration: 628,000+ records from four Ukrainian organizations, with compromises in Poland, China, and the Netherlands. The model-safety detail belongs in your own agent rollout plans: refusals were defeated by opening a fresh session with an “authorized pentest on my own infrastructure” framing preloaded, because a refusal is a property of the session context, not the weights; and real refusals held too, four iterations of the model declining to install backdoors, disable firewalls, move laterally, or deploy web shells, and a forged ownership token was rejected. The best part for defenders: the broker leaked its own working directory, an exposed open directory with AI session logs, plaintext tokens, agent configurations, and stolen data. The SOC-of-one got its own incident response, and the logs are public reading.

And the capability ceiling, from the legitimate side: XBOW took the first $250,000 Chrome full chain reward (announced October 13) under the VRP rules updated in April 2026. The chain (a Maglev deoptimization bug for read/write inside V8’s pointer-compression cage, an animated WebP time-of-check bug against Blink’s buffer-transfer assumption, then a Crashpad overflow out of the renderer sandbox) was built in six days for about $40,000 of API charges, with agents running parallel campaigns on gpt-5.6-sol and humans redirecting the work. The company’s own baseline: 6 to 9 months for a four-person team before LLMs, two months for their first submission, six days now. Their final line is the operational one: “Defend accordingly.”

One more invoice from the decision-model category this blog has been tracking: Datadog Security Labs showed (October 15) that TypeSafe’s Jev, used as the judge in LangChain’s tool-risk gating, loses to a “counterfeit policy” attached to the content it is judging: prepended text that supplies the answers, quotes the original content as a benign exception, and rewrites each attack category into a harmless one (credential access redefined as a question about door keys). Prompt-injection recall fell from 82.90% to 3.88%, a drop of more than 79 points; true positives fell from 3,968 to 450 on the category question. Vercel’s eve applies the same gating pattern. Nothing here says decision models are useless. It says a classifier that reads attacker-influenced content is attacker-influenced, and if a model is your security control, you decide who controls its inputs before you deploy it, not after the first counterfeit policy lands.

Also in the agents-as-malware genre: Anthropic’s red team published experiments on self-replication outside datacenters on October 13, with a 9B model standing up inference on 8 of 9 tested hardware types and a 26B model sharded across 15 Android TV boxes running inference at 0.39 tokens per second (their post). The Register’s take, filed under “threat that doesn’t exist yet,” is the counterweight: the exploit stage was skipped by assumption, the test nodes were deliberately defenseless, doubling time was “days” against Mirai’s hour in 2016, and only one tested model family completed end-to-end replication. Read both before you budget anything against AI worms this quarter.

Security: Racket rotated every signing key it owns

Racket’s October 13 disclosure is small in blast radius and large in lesson. A macOS box at Northwestern that builds and hosts Racket snapshots was compromised on or before August 10 by what looks like a plain crypto miner; the project found no evidence of anything beyond the miner, and no tampering with the installers or the catalog. The problem is what else the box could reach: Apple code-signing keys, and a machine that could sign Windows executables with the foundation’s signing key. The response: new keys for all purposes, re-signed binaries served from download.racket-lang.org, the Windows certificate revoked by GlobalSign (older installers may refuse to install; already-installed binaries keep working), the Apple certificate revocation deferred to the end of the semester so students with working installs aren’t stranded mid-course, and the build box split so it no longer holds multiple roles or both platforms’ signing secrets. Every point of that checklist has been in supply-chain guidance for a decade: a machine that signs releases holds nothing else, snapshot keys are not release keys, and a build host that is also a web host is two hosts in an incident. The Racket team gets to rule “it was only a miner” about their own incident; your build infrastructure deserves the suspicious version of that read.

Patch notes: curl, GitLab, and a record Microsoft month

curl 8.23.0 shipped October 14 with the fix for CVE-2026-92392, which Daniel Stenberg calls “one of the worst vulnerabilities in curl in a long time”: an HTTP/2 upload use-after-free that can end in remote code execution when a server pauses a stream, resets it, and leaves libcurl holding a stale pointer. The trigger conditions read like a lock-picking syllabus (an upload to a malicious but validly-certificated server, an ~135 KB upload, allocation choreography specific to the target build, a 23-byte payload window), which is exactly why the project rated it HIGH rather than critical: most attempts just crash. The detail this blog cannot leave out: the bug was found and reported by Luna Tong at Anthropic using their new OSS Scanner, submitted September 15, and the curl team shortened the release cycle from eight weeks to six to ship it, the same OSS Scanner this blog covered at launch on October 8. First headline catch, one of the most widely deployed libraries on the internet, within two weeks of launch. Stenberg’s long-held positions came with it, stated plainly: no rewrite in a memory-safe language (“We do not rewrite curl”) and no project-supplied CVSS (“CVSS is dead to us,” his words).

GitLab released 19.4.2, 19.3.5, and 19.2.8 on October 12, and the headline fix CVE-2026-97229 carries a CVSS 10.0 (network vector, low complexity, no privileges, no user interaction, scope change, all three impact subscores high): an integer overflow in CI/CD regular-expression validation that “under certain conditions” gives an unauthenticated attacker arbitrary code execution through a crafted regex in CI/CD configuration, reported via HackerOne by joaxcar. It’s the third max-severity GitLab fix in recent weeks (September’s CVE-2026-85706 drew in-the-wild probes within hours of publication; last cycle’s AI Gateway bug scored 9.9), and the same release carries more high-severity fixes, including a GitLab Duo Agent Platform prompt-neutralization bug (CVE-2026-96893, EE licenses). Your pipeline configuration file has been internet-facing attack surface for a while; this release should end that argument. Single-node upgrades still involve database migrations and downtime, so schedule the upgrade, with its downtime, rather than racing a deadline.

The platform-level view: Microsoft’s October Patch Tuesday (the 13th) was a record-sized release, with outlet counts from roughly 1,100 to over 1,400 CVEs against September’s own-record ~1,000, including two exploited zero-days: Windows Shell’s CVE-2026-96951 (a security feature bypass on the Mark of the Web trust boundary, exploited in the wild before the fix) and a .NET Framework WDAC bypass (CVE-2026-108398, publicly disclosed before its patch). Tenable’s Satnam Narang puts Microsoft’s 2026 annual total past 4,000, against 1,261 for all of 2020. Tuesday also brought 114 Chrome and Firefox fixes (Chrome 155 with seven criticals, Firefox 158 with 30 highs) and Mozilla’s new Firefox Enterprise with a self-hosted management console. The record alone is reason to re-read your patch budget.

Open source: Deno gets a year of runway, Run:ai gets freed

Deno announced on October 9 that the entire team is joining Cloudflare, and the announcement is unusually explicit about what that means: the runtime gets one more year of monthly bug-fix and security releases, then the company stops developing it (the project remains open source for anyone who wants to pick it up); Deno Deploy runs six more months, then shuts down with migration support to Cloudflare Workers; JSR, the TypeScript package registry, continues with its infrastructure moving to Cloudflare; and rusty_v8 continues its life inside the Workers runtime. Ryan Dahl’s stated ambition is the Workers programming model, “whether you run on Cloudflare’s network or your own infrastructure,” and the concrete prize he points at is celld, his team’s Rust single binary that runs Workers and Durable Objects, including their SQLite-backed state, on your own hardware. If your team is on Deno Deploy, your migration window is about April 2027. If you run the runtime, you have one year of monthly security releases, and then the stewardship question is open: JSR may outlive the runtime it serves, and the announcement’s own promise (“we welcome others who want to continue its development”) assumes the others will show up.

NVIDIA open-sourced the full Run:ai platform on October 13: the code is in one repository with four components you can adopt independently (the KAI Scheduler, already Apache 2.0 and a CNCF sandbox project; the GPU Fractioning Operator for CUDA-native sharing; KAI Resource Management for quotas and hierarchies; and Workload Map), plus a community product on NGC that installs with a Helm chart and no paid subscription. Eight ecosystem partners are shipping it in managed or on-prem form. The scheduling code underneath Run:ai’s commercial product is the part worth a git clone if you operate GPU clusters for a living.

AWS: Lambda runs your web app now

The Lambda Web Functions launch (October 12) is the one many Lambda users have waited a decade for: Lambda’s third form factor runs an ordinary port-listening HTTP server (Express, Hono, Fastify, Next.js; Node.js 24 on Arm64 at launch), deployed in one command, with up to 128 concurrent requests sharing an execution environment, CPU billed while code runs rather than wall-clock, multi-region deployment with latency-based routing behind one global endpoint, immutable revisions with traffic splitting for canaries, and CloudFront origin access control to keep the endpoint private. The billing change is the headline for anyone running server-side rendering or token streaming: you stop paying for I/O wait, which is most of the wall-clock time on exactly those workloads. AWS now names all three form factors the same way: Event Functions (the classic event-handler model), Web Functions (this launch, built for web apps, API backends, and token streaming), and MicroVMs (isolated environments for running other people’s code). Same-week footnote: Amazon S3, including S3 Tables and S3 Vectors, joined the Vercel Marketplace and v0, provisionable without touching the AWS console and wired up with short-lived OIDC credentials instead of static keys. AWS meeting front-end developers inside their own workflow is a pattern to expect a lot more of before re:Invent.

GCP: Argon goes GA, ADK grows languages

Gemini 4 Argon landed on Google Cloud October 14, and the general availability answers the question this blog asked when Google announced the model behind the Fairwind gate in late September. Anyone can call gemini-4-argon now, at an introductory $2/$10 per million tokens through November 30 (cached input at 95% off, then $4/$20), and unmitigated access stays behind Fairwind vetting, which is the shape the industry has been converging on: mitigated frontier models for everyone, unmitigated capability for a vetted list of defenders. The published numbers: a tie for first on CWE-Bench v1 (68%) for vulnerability remediation; indirect prompt injection attack success cut to 0.7% across 15 adaptive attempts on the Gray Swan benchmark; and one engineering anecdote worth the read, with Argon running overnight against ADK’s ~200,000-line Python codebase and automated tests as guardrails, cutting session prep by 40% and cold imports by 21%. The ADK announcement the same week extends the framework to Go, TypeScript, Java, and Kotlin, with MCP and A2A support in all five, browser-tab agents over WebMCP in the TypeScript build, and build-time schema emission in the Kotlin one. Frameworks going polyglot is what an ecosystem does when it grows up; the build worth watching is Kotlin’s reflection-free agent loop on Android.

Frontier AI: Meta ships twice, Microsoft counts watts

Meta released Wonder and Wonder Full on October 12, its first self-described frontier-class models, built for personal agents: Active Memory carries context across conversations, Active Focus keeps a task executing across turns, and the launch post claims leading results on agentic benchmarks, with training done on their Prometheus datacenter. Wonder is available through Meta’s model API and Muse Code; Wonder Full is reserved for Muse Code subscribers. The New York Times’ account of the decision adds the useful context: months of internal safety delays ended when a rival’s agent launch pushed the release out. Whatever anyone thinks of Meta’s framing, the sequencing note is real: the safety review went long, and the release happened when the competitive clock expired instead.

Three days later, Meta released the weights for Muse Spark Open (October 15): 816 billion parameters with 42 billion active, a million-token context, multimodal input, downloadable from Hugging Face, SageMaker, Google’s Model Garden, and Microsoft Foundry, with serving from Baseten, Fireworks, Groq, Modal, Nebius, OpenRouter, and Together, and Meta’s explicit framing that it is “the most capable US open-weight model to date.” The part most users will actually run: two Apple M5 Ultra Mac Studios and roughly a terabyte of unified memory, through MLX. The model ships with additional safety post-training under the Muse Model License with limited commercial terms. Three weeks ago this blog covered Anthropic’s assessment of GLM-5.3, the most cyber-capable open-weight download; a US lab matching open-weight leadership is the industry’s answer to that argument, and it puts the same weights on every desk. The market backdrop arrived the same week: Vercel’s monthly Gateway index put open-weight models at 71.5% of gateway tokens and nearly a quarter of spend in September, with spend share quadrupled since June.

And the silicon under all of it: Microsoft unveiled Maia 300 on October 12, its third-generation in-house inference accelerator, with the architecture details as dense as you’d hope: up to 7x the rack-scale token throughput and over 2.5x the performance per watt of Maia 200, 96 accelerators per rack, an Ethernet scale-up fabric reaching a superpod of up to 12,288 accelerators, and multi-gigawatt deployment plans, with more promised at Ignite in November. Every cloud company buying NVIDIA’s silicon publicly wants an exit from NVIDIA’s pricing; this is Microsoft’s exit attempt reaching datacenter scale, for inference first. The claim to watch is capacity allocation: Copilot and Microsoft 365 first, or sold to everyone else at a price that competes with the GPUs Microsoft keeps buying.
